# 业务知识库（模拟）

> 本文件模拟真实电商公司的业务知识沉淀，供 agent 的知识检索（RAG）使用。
> 检索按章节切块：每一段 `##` / `###` 是一个可召回的知识单元。
> 内容均为演示数据，与 `ds_agent/data/synthetic.py` 生成的演示数仓一一对应。

## 指标口径

### GMV（成交总额）

GMV 统计**下单时刻**的订单金额，包含未支付订单，**不扣除退款**。
因此 GMV 与财务口径的"确认收入"（revenue）天然不等：大促后 GMV 会虚高，
退款率（≈8%）回落后才与 revenue 接近。对内汇报默认用 GMV，对财务汇报用 revenue。
`orders_daily.gmv` 与 `experiment_users.revenue` 是两张不同的表：前者是订单日汇总，
后者是用户级实验窗口内的金额，**不可直接相加对比**。

### 转化率（CVR / converted）

转化率 = 下单用户数 / 访问用户数，按"人"去重，不按订单去重。
跨日窗口时一个人多次访问只计一次访问。分母（访客）来自埋点，受埋点丢失影响：
iOS 端埋点丢失率约 3%，所以 iOS 的转化率**系统性偏高**，跨端对比需说明。

### ARPU 与人均 revenue

ARPU = revenue / 活跃用户数（DAU 口径随窗口变化）。
对比实验的 ARPU 时必须用同一窗口的活跃口径，"实验期活跃"与"全量活跃"不可混用。

### 退款率

退款率 = 退款金额 / 支付金额，退款有 T+1 延迟：当天看到的退款率至少低估一天，
评估售后改动时观察窗口要往后多留 3 天。

## 维度语义

### 渠道（channel）

- **feed**：信息流推荐。流量最大、波动也最大，受上游推荐策略调整影响明显；
  埋点规则与其它渠道不同（曝光在客户端上报）。
- **search**：搜索。意图最强、转化率最高的渠道；大促期间占比自然上升。
- **direct**：直达/老用户。波动小，常被用作"稳定基线"对照渠道。
- **promo**：活动页渠道。只在活动期有量，非活动期为 0 属正常。

### 设备（device）

iOS / Android 两端。iOS 用户客单价高但埋点丢失多；任何跨设备结论都要先检查埋点缺失。

### 地区（region）

华东 / 华北 / 华南 / 西南 等。华东体量最大；西南在演示数据中是补贴政策试点地区
（`city_panel.treated`），做因果分析时其它地区是天然对照组。

## 业务规则与已知坑

### feed 渠道埋点中断（2026-10-15）

2026-10-15 起 feed 渠道客户端埋点上报中断约 11 天，GMV 下单数据本身正常，
但访客数（分母）偏低，导致 feed 转化率虚高、总体 DAU 口径偏低。
分析这段时间的数据时：GMV 可以用，转化率与 DAU 相关结论要剔除 feed 或注明。

### iOS 支付 SDK 回退（2026-10-15 起）

同期 iOS 支付 SDK 回退到旧版本，支付成功率下降，GMV 受影响约 -7% 量级。
这是演示数据中"近 11 天 GMV 下跌"的第二起因。两起事件同时发生，
单靠指标数据无法区分渠道埋点问题与支付问题，需结合本知识库标注。

### 大促日历

618（6 月中）、双 11（11 月上）、年货节（1 月下）为大促节点，GMV 环比在节点前后
不可直接比较。演示数据为日常数据，不含大促尖峰；真实数据请先对齐日历再算环比。

### 企业采购订单

region=华南 的 `channel=direct` 偶发超大额订单（单笔可达日常均值百倍），
属正常企业采购，**不要当异常值清洗**，但算均值类指标时应单独说明或用中位数。

## 数据字典

### orders_daily

日粒度订单汇总：`date, channel, device, region, category, orders, visitors, gmv, paid_gmv, refunds`。
180 天，适合异常检测、归因、时序因果（ITS）的演示。

### experiment_users

用户级 A/B 实验数据：`user_id, group(treatment/control), device, converted, revenue, pre_revenue`。
真实转化率相对提升 +6%；`pre_revenue` 是 CUPED 协变量。

### city_panel

城市×周面板：`city, week, gmv, treated, post`。第 26 周起 6 个试点城市有 +9% 政策效应，
适合 DiD / 合成控制演示。

### promo_users

促销曝光观测数据：`user_id, promo, pre_revenue, post_revenue, tenure_months, sessions_30d`。
曝光非随机（高价值用户更可能被选），真实 ATE=12 元；适合 PSM/IPW/AIPW 演示。

### switchback_log / reverse_log / two_sided_market / nested_users / uplift_users / rdd_scores / its_series

分别是时间片轮转、反转实验、双边市场 2×2、父子实验、uplift（真实 ATE=12.5）、
断点回归（cutoff=600，真实跳跃 +22）、中断时间序列（干预后 +12%）的演示表。

## 常见问题（FAQ）

### 为什么 GMV 跌了但 revenue 没跌？

先查退款率与未支付订单：GMV 含未支付，支付成功率下降只影响 GMV 前段；
若只有 iOS 跌，优先排查支付 SDK（见"iOS 支付 SDK 回退"）。

### 为什么转化率涨了但 GMV 跌了？

转化率分母是访客。feed 埋点中断会让分母偏小、转化率虚高（见"feed 渠道埋点中断"）。
遇"率涨量跌"先怀疑分母口径，再看分子。

### 跨渠道对比的正确姿势

feed/search/direct 的埋点规则不同，绝对值对比前先看数据字典与埋点备注；
趋势对比建议各渠道用自己的历史做归一。
